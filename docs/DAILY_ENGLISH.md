# 日常英语首批交付

日期：首批内容 2026-09-15；学习结构更新 2026-09-22。

## 当前学习结构（优先于下方历史验收描述）

现在为“课程、复习、表达库、收藏”四个入口，课程与练习册合并。课程页只显示当前动态编排的一节，下一节根据实际表现选择薄弱旧内容并酌量增加新内容；不预先锁定实际课数，也不展示未来课名或单元名。原 24 课是教学材料范围。表达库使用原 83 条表达与静态录音，支持查询、收藏、学习状态。“收藏”直接展示原 `codewords-daily-v1` 中的表达收藏，搜索与表达库筛选独立，可逐条正常／慢速点读或取消收藏；不修改课程和复习证据。

确认教学后登记“正在学习”，按表达或稳定知识 ID 记录首次学习和理解、听力、书写、口语表现；第一次教学不准入长期复习。本轮逐题加权随机选择不同题面，先识别，再按表现安排语境和回忆；错误多时后续节多补旧内容，不硬性规定每个表达的练习次数。

只有信心与间隔迁移证据满足条件，才记录 `readyAt` 并进入长期复习；Hello、Goodbye 等简短表达可以通过回忆形成证据，不要求都有语境题。口语跟读与自查可以保留在练习中，但不自动增加信心或准入证据。长期复习出现的新困难会回流下一节补学，已取得的准入资格保留。

未测能力保持未测；历史课级数据不改写成逐表达历史。`knowledge`、`favorites`、`learning` 和会话 `adaptive` 都是兼容扩展，仍使用原 `codewords-daily-v1`。计划、随机状态、题目、草稿与反馈持久保存，刷新不重新抽当前题。`src/dailyPractice.ts` 在原英文与录音之上提供候选题，不新增运行时 AI 或后台服务。

`DailyEnglish.tsx` 和状态函数也被编程课程复用，但课程内容和存储键独立。下方标注为历史的固定课数、练习册入口和旧验收记录不代表当前动态流程；当前规则及分阶段验证见 [课程系统说明](COURSE_SYSTEM.md)。

## 如何使用

1. 进入日常英语，开始或继续当前一节。先阅读本节说明、点读相关表达，再开始练习。
2. 练习包含选择、听音、词块排序、渐进填空、写句和少量表达自查。选择后先检查，再继续；系统根据已存表现选择下一题，穿插不同目标。有限预算结束后，未稳定内容留给后续动态课。
3. 多空题可用 Tab / Shift+Tab、空格和方向键移动；单字母空自动前进。Enter 检查，反馈后 Enter 继续。输入法组合期间不提交。开放表达使用 Ctrl + Enter 完成自查。
4. 原练习册已经合并到课程。“复习”只练已准入的表达，可到期练习、按能力选择或提前巩固；刚确认教学的表达继续留在课程学习期。
5. 离开课程、切换分区或刷新后，从“继续上次学习”恢复。当前题目、草稿、提示、反馈、纠错队列和结果均保存。

一次保留一轮进行中的练习。切换到另一课前页面会说明：已答记录保留，当前未提交输入不再续接；可以选择继续原课。切换界面风格、语音偏好或编程分区不结束当前日常课程。

原材料的 12 道口语题保留“跟读示例 / 自己表达”，动态课程仅在目标已介绍后少量安排，每轮最多一题。跟读时逐句点击麦克风，允许权限后开口读；识别文字与参考表达逐词对齐，标出未识别到的词、识别成其他词和多余词，可直接重读。全部句子匹配后完成跟读。问候材料包含 Hello 和 Goodbye；姓名等可变信息通过“自己表达”练习，不强制与示例姓名一致。

自己表达可用麦克风转成文字，也可手动填写、纠正识别结果，然后核对原题自查项。口语记录仍使用原来的 `self` 类别，不因此提升独立掌握或隔日记忆等级；没有自动发音、语法或作文评分。完整实现、使用限制和本次测试见 [口语识别接入](SPEAKING_PRACTICE.md)。

## 书写判题

填空结合题面组成完整句子后检查，写句和词块排序使用同一套书写匹配。例如 `I [空] Mia.` 接受 `am`、`’m`、`m`，不会因空格中没有完整的 `am` 而误判。

大小写、句末标点、多余空格及中英文撇号不影响结果；常见缩写和完整形式按句子匹配。没有限定句式的题目还收录明确等价的表达，例如“我叫 Ben”接受 `I’m Ben` 和 `My name is Ben`。美国名称的缩写及全称均可填写。

宽容处理不采用编辑距离猜词：人名、否定、单复数、缺词以及题目明确指定的句式仍参与判断。简短肯定回答保留完整形式，例如 `Yes, I am`；不能把 `Yes, I’m` 当作同义正确答案。口语识别、纠错安排和已有记录的存储格式不变。

回归脚本：`tools/test-written-answer.mjs`、`tools/test-daily-tolerance.mjs`；真实页面回归为 `tools/test-daily-tolerance-browser.mjs`，使用与下方浏览器验收相同的环境变量。

历史判题修复验收：TypeScript、115 项 Node 测试、生产构建和资源完整性通过。隔离 Chrome 完成当时 24 课全部主练习及原有 10 组日常场景；新增 16 个宽容判题场景在开发页面和构建成品均通过，涵盖 `m`、后续缩写、等价回答、多词填空键盘输入、确实答错和刷新保留。构建成品的两区真实点读及静态资源路径检查也通过。历史截图：[1440px](../artifacts/answer-tolerance/m-correct-1440.png)、[390px](../artifacts/answer-tolerance/m-correct-390.png)。已有历史答题记录不追溯改写。这些结果验证当时判题流程，不替代当前动态课程验收。

## 记录与兼容

- `codewords-daily-v1`：版本、材料完成记录、表达知识、收藏、理解/听力/书写/口语自查证据、错误，以及可选 `learning` 和带 `adaptive` 计划的当前学习会话。
- 当前草稿可带可选 `speech: { mode, transcripts }`，按参考句 ID 保存最终识别文字，旧草稿没有此字段仍可读取。未完成的临时识别不写入进度；不保存录音。
- `codewords-section`：最后选择的学习分区。
- 沿用 `codewords-theme`、`codewords-voice` 和 `codewords-playback-speed` 作为共享偏好。
- 原有编程英语的掌握、收藏、测验、渐进复习等存储键、词汇 ID 与规则不迁移。相同单词在两个分区出现，不自动互相标记掌握。
- 材料已介绍、动态节完成、长期复习准入、当次独立作答、跨日回忆及表达自查是不同证据；同日重复、看提示和立即纠正不会冒充跨日记忆。
- 损坏或未知版本记录保持原文，不覆盖为空记录。另一标签页更新记录时，旧页面停止保存，避免覆盖新进度；存储失败同样提示并保留本页输入。
- 正常可导出当前记录；出现保存问题时导出文件同时包含原存储文本与本页最新状态，以免遗漏未保存的草稿。当前没有自动导入或跨设备同步功能。

## 音频与构建

`public/audio/daily/aria/` 和 `public/audio/daily/guy/` 各有 83 个 MP3，共 166 个，约 2.25 MB。每个文件的文本、声线、合成参数、文件哈希和解码信息均在独立 `neural-manifest.json` 中记录。

生成只写日常音频目录：

```powershell
.venv/Scripts/python.exe tools/generate_daily_audio.py
python tools/verify_daily_audio.py
```

它使用已有 edge-tts 环境，没有新增前端依赖。示范点读只播放静态 MP3；麦克风识别另使用浏览器原生 SpeechRecognition。英文文本变化时按内容哈希更新；页面 URL 同时带文本版本，防止旧缓存与新文字不一致。

`npm run build` 校验构建副本，`npm run verify` 校验源目录；快速校验覆盖文件集合、文本、声线、合成参数和文件 SHA-256。完整音频解码额外运行 `tools/verify_daily_audio.py`，不把 FFmpeg 引入普通构建的依赖。

构建使用 Node.js 24，日常课程数据校验最低需要 Node.js 22.18。原有 3,560 词的身份基线保留，补充后当前共 3,620 词、Aria/Guy 各 7,241 个编程录音；旧 Piper 7,122 个音频继续冻结检查。它们与本分区 166 个日常录音分别校验。
