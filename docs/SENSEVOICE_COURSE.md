# SenseVoice 本机课程识别

## 接入范围

日常英语口语题在桌面浏览器打开时，会检测本机 `127.0.0.1:18768` 的 SenseVoiceSmall 服务。服务可用时，点击课程原有麦克风按钮录音；读完点击结束，浏览器只把本次录音送到本机回环接口，模型返回识别文字。课程沿用原有文字核对、重读及自我表达路径。服务不可用时，仍使用原有浏览器识别；Android 仍使用原有系统识别。录音不保存，识别文字按原有学习进度格式保存。

本机服务不会接收题目参考答案，只有识别后的文字由前端和题目比较。识别文字一致不代表每个音都正确；文字不一致也不代表用户发错音。口语自查不增加掌握或长期复习准入证据。

## 免费与速度

模型权重来自 FunAudioLLM / 阿里巴巴的 SenseVoiceSmall，本机推理无按次 API 费用、无试用期。模型以 [FunASR Model Open Source License Agreement 1.1](https://github.com/modelscope/FunASR/blob/main/MODEL_LICENSE) 提供，使用时需保留来源和模型名；ONNX 转换来自 [danieldong/sensevoice-small-onnx-quant](https://www.modelscope.cn/models/danieldong/sensevoice-small-onnx-quant)。此处仅核对当前个人本机使用，未对未来商业发布作法律结论。

固定公开样本中，预热后的短词模型计算中位约 60 毫秒；新增课程转写方法对公开 Goodbye 音频返回 `goodbye`，模型 72 毫秒、含解码和语音检测 111 毫秒。首次载入约 4.8 秒。用户实际等待还包括自己录音时间、浏览器录音封装、传输和界面处理，不能把 60 毫秒说成完整体验耗时。

## 本机启动

项目的 `scripts/Open-LocalSite.ps1` 在确认网站和服务身份后，尝试从已隔离的 `.runtime/pronunciation/mdd-venv` 启动服务；模型和环境不进入 Git、网页构建或 APK。端口被其他进程占用时不强行停止。启动失败时网页仍可使用原识别路径。本地服务只接受已列明的 CodeWords 网站来源及一次启动内的随机令牌，请求须从 `127.0.0.1` 到达。

旧服务版本没有 `/api/course-session` 接口。最初尝试重启旧进程时，执行工具返回 `blocked by policy`，没有继续用别的方式中断该进程。随后独立核对发现旧监听已消失，才在空闲端口启动新版服务。新版健康检查及课程会话接口均返回预期版本。

2026-09-27 已用公开 Goodbye WAV 驱动 Chrome 的真实 MediaRecorder，完成课程麦克风入口 → 新版本机 HTTP 服务 → SenseVoiceSmall → 文字回填的端到端测试。返回 `goodbye`，请求未包含参考答案，刷新后记录保留，未增加自动掌握证据；390 像素页面没有横向溢出。最近一次完整链路的服务端解码、检测及推理为 159 毫秒，点击结束录音到页面显示约 212 毫秒（不含用户录音时间，单次样本，不是时延保证）。另用模拟接口验证界面布线，原浏览器识别的九项生命周期／回退场景也通过。真实测试使用公开音频和隔离浏览器环境，不是用户本人新录音。Android 原生识别和已部署 HTTPS 网站到本机服务的链路未在本轮实测。

## 已知局限

- 标准 `Tree` 音频曾被识别为 `three`。界面只显示文字差异并允许重试，不自动判用户读错。
- 现有真人反馈是用户试读熟悉词时识别正确的自述；无逐次词目和结果，不能换算准确率。
- SenseVoice 是语音转文字模型，不输出可信的具体错音。逐音纠错仍是单独未完成的能力。
- 手机 APK 不包含这套约 938 MB 的 ONNX 模型。手机不在同一台电脑上，`127.0.0.1` 也不是电脑地址，因此此次接入只覆盖装有本机服务的桌面浏览器。
