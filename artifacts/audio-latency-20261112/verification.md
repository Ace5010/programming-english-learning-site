# 在线点读延迟修复验收

状态：本地修复和验证完成，尚未提交、推送或发布。沿用原分支；开始时已有的三个 Android 测试／产物改动未纳入本次修改。

## 复现与原因

- 当前线上地址：`https://programming-english-learning-site.pages.dev/`。
- 新建隔离 Chrome 上下文，首页加载后点读正常单词、例句、慢速单词。预热后的普通音频约 17ms 开始，慢速单词仍增加一次同包请求，约 785ms 才触发播放事件。该事件只用于记录启动耗时；后续检查发现旧播放器在无范围支持时还会定位失败。
- 本机当前网络路径的 HTTP 检查：音频 `Cache-Control: public, max-age=0, must-revalidate`；发送 `Range: bytes=100000-101000`，服务器仍返回 200 和完整音频包。
- 原慢速播放器另建媒体元素；原词库预加载仅覆盖前 6 条。滚动后的新词以及缓存被丢弃的录音会在点击时产生网络等待。
- 原版播放器（基线提交 `70fd8369`）在模拟 900ms 延迟、200-only 响应下再次复现：预热后点击仍约 931ms 才触发播放，从包首错误位置开始，随后 watchdog 报错。回归明确把这一例标为预期的基线失败。

证据：`online-before/results.json`、`online-before/network.json`、`regression/results.json`。

## 修复

- 普通读音按词库／收藏／复习列表视口提前加载，保留录音路径及版本参数；点读文字的预加载同时覆盖普通录音。
- 慢速及语境音频包完整下载到有上限的临时 Blob 缓存，支持在返回 200 的静态服务器上准确定位；复用已加载的媒体元素，并保留整句的单元素播放。
- 处理取消、旧异步回调、错误后重试、缓存淘汰与对象 URL 回收。安卓本地 origin 保持既有资源通道。
- 为静态音频添加一天的 HTTP 缓存；CSP 的 `media-src` 增加 `blob:`。
- 没有更改学习记录格式、词汇／录音内容、课程规则或界面文案。
