# 准确性优先与国内入口筛选（2026-09-25）

本轮新增约束：优先准确理解用户口音，延迟其次；获取模型和日常使用均不能依赖 VPN；继续优先免费方案。没有新增付费调用，没有上传用户录音，没有保存新录音。

## 国内入口与费用

- Qwen3-ASR-1.7B：阿里官方提供 [魔搭模型仓库](https://www.modelscope.cn/models/Qwen/Qwen3-ASR-1.7B)，可下载到本机运行，不调用计费 API。实际模型文件约 4.70 GB；这不是收费在线服务或限时试用。
- 直接网络检查：测试进程关闭环境代理，并用 Windows `IP_UNICAST_IF` 将 IPv4 请求指定到已经核实的物理以太网。模型页、配置和权重文件前 1 MiB 均成功返回，权重片段与下载片段一致。没有更改系统路由或关闭全局 VPN。证据：[网络检查](modelscope-direct-network.json)。检查覆盖本机当时的网络与入口，不等于所有运营商及所有浏览器资源的长期可用性保证。
- 推理阶段单独禁用网络，模型下载与私人录音处理分开。Qwen 官方将它定位为语音识别；转写正确不等于能可靠判定每个音的发音质量。
- KoelLabs 需要 Hugging Face 登录及向作者共享联系信息。用户追加普通网络入口要求后，暂停此路线，未提交访问申请、未开通付费服务、未绕过下载权限。

## Qwen3-ASR 实测

完成 48 个公开用例、3 类无语音控制及两段分别授权的本机录音各 3 次。使用官方 `qwen-asr==0.0.6` wheel 内的 Transformers backend，保留原始权重和预处理；不安装与此次英文转写无关的网页服务及日语/韩语强制对齐依赖。指定 English，context 为空，不把目标单词、答案列表或相似词注入模型。CPU float32 推理，不用量化换速度。

- 24 个公开合成单词用例全部转写为实际播放的词；其中 10 个错词未被改写成目标答案。现有 Whisper small 在这组材料的原始词转写也为 24/24，不能据此声称 Qwen 已超过现有方案。
- 12 条专家认可的成人读法中，10 条文字完全一致；另外两条是 found→find、dock→doc。后者是同音拼写差异，不能作为发音错误。
- 12 条专家标有明显发音问题的句子中，7 条仍转写成目标原句。这再次说明准确转写与逐音纠错是不同能力，不能用“文字一样”替代发音评测。
- 合成短词模型计算时间中位 1.541 秒，真人短句约 2.8—5.7 秒，不含录音、文件解码、网页传输或模型首次加载。私人样本没有同时改善，暂不替换当前引擎。
- 静音、噪声、纯音分别输出 Yeah、Okay、Oh；原始识别器不能独立承担静音拒绝和课程通过判断。
- 主权重版本 `d69410f1c275f2b0fa60cbb9960edfcdb0ae0aec`；文件级 SHA256、版本、所有输出与耗时见 [Qwen 原始报告](qwen3-asr-screening.json)。严格加载没有缺失或多余权重，推理进程禁用网络。

另做一次预处理开发排查：按音频自身峰值归一化至 0.7、增益上限 20 倍，未使用目标答案决定增益。两段已授权录音均没有改善，原本能识别的一段反而失败，因此未采用。此探索不计入固定基准，详细结果仍只保存在本机忽略目录。

## SenseVoiceSmall 对照

完成相同 48 个公开用例、3 类无语音控制，以及两段分别授权的本机录音各 3 次。模型通过魔搭获取，页面及完整 938 MB ONNX 权重使用物理以太网接口 9、关闭环境代理；没有改动系统路由。下载普通网络耗时较长，最终文件完整校验通过。使用社区发布的 FP32 ONNX 转换，原始模型、配置、归一化参数和词表的发布哈希与 `iic/SenseVoiceSmall` 官方仓库一致；这不等于已经证明转换图与 PyTorch 数值完全一致。见 [来源及入口验证](sensevoice-source-check.json)。

- 14 个正确合成词全部转写正确；10 个错词未被转写成目标答案，其中 Aria 的 bed 被转写成 de，其余 9 个还原了实际错词。实际词转写为 23/24，合成短词计算时间中位 60 毫秒。
- 12 条专家认可成人句子中，9 条文字完全匹配；误识别为 found→find、dock→dog、time→ten。整句转写未优于 Qwen，不能把私人短词的改善推广到全部英文识别。
- 12 条专家标注有明显发音问题的句子中，6 条仍转写为原文；模型没有逐音纠错能力。
- 两段用户授权录音均连续三次转写为意图词，计算时间约 61—78 毫秒。这是仅有两段录音的复测，不是六个独立样本；详细输出保留在本机忽略目录，未放入公开结果文件。
- 静音、噪声、纯音均输出 y，不能直接用原始转写控制课程通过。后续试读必须另外验证无语音拒绝。
- 采用官方 `funasr-onnx==0.4.1` wheel 的未修改特征提取代码及发布方的贪心 CTC 解码流程；English、无答案提示、无热词、不修改原录音音量。只在已隔离的实验环境新增 `kaldi-native-fbank==1.22.3`，未修改前端依赖或生产服务。
- ONNX revision：`0fa75a7bcea5a24a858c77c06d2e6d8a3d72c4ab`，SHA256：`db9df447f53ab277db1a10335173f739d25444abb2eb961fc4f88e98b5f03122`。原始报告：[SenseVoice](sensevoice-screening.json)。首次加载约 4.8 秒；表述的毫秒数均是预热后模型与预处理时间，不包含录音、音频解码、网页传输或首次加载。

就“先理解用户的短词、普通网络获取、免费本机运行”这一步，SenseVoice 目前值得优先进入新录音试读；尚不足以接入正式自动发音判定，也没有全面超过 Qwen 的英语句子准确率。

## 已缓存较大 Whisper 的补查

在同一台电脑用已下载的 Whisper large-v3（INT8、4 CPU 线程、beam size 3、无答案提示）复核两段分别授权录音，各重复三次；无下载、无云端调用。Goodbye 稳定，但另一段录音的文字输出在重复间变化，约 13.9—14.1 秒，低置信度。保留 faster-whisper 默认温度回退，所以这三次并非确定性解码。该结果不支持替换当前方案，也没有验证该缓存模型的国内重新获取路径。详细私人结果仅存 `.runtime/pronunciation/private-diagnostic/whisper-larger-accent-recheck.json`。

## 2026-09-26 本机试读

新增独立 SenseVoice 试读页 `http://127.0.0.1:18767/`：浏览器录音只送往本机回环服务，服务端不保存音频或转写，不修改课程进度。页面只显示模型识别的文字及其与目标词是否一致；文字一致不自动判定发音合格，也不显示未经验证的具体错音。

在识别前加入已有 faster-whisper 包内的 Silero 语音检测器。固定设置下，两段分别授权保存的真人录音和 24 条公开单词音频均被检测为语音；静音、固定随机噪声和纯音均被拦下。这是限定测试集的结果，不证明所有环境噪声和正常低音量发音都能正确区分。

本机 HTTP 实链路以公开 Goodbye、sink（目标 Think）、静音和未授权请求检查：分别返回正确文字、不同文字、无语音和 403；均没有发音评分。Chrome 假麦克风播放公开 Goodbye 后经 MediaRecorder 与真实本机服务得到识别结果，320、390、1280 像素布局无横向溢出，页面无脚本错误。这项自动浏览器测试不能代替用户真实麦克风体验。

用户随后在真实试读中反馈“这次好像还行”。这是初步正向体验；试读页不记录音频或逐次结果，当前未知用户本次试了哪些词及每词识别情况，尚不能计算真人准确率。下一步需要基于新的不同词真实录音核对误识别、易混词和音量条件，再决定是否推广至课程。当前试读服务健康检查通过。

用户进一步说明部分试读词不认识，也不确定自己是否念对。原试读方式无法把词本身不熟悉与识别误差区分开，因此这次主观体验不能计作已验证的准确率。另用完整本机 HTTP 链路核对 15 个预设词及其示范音频：14 个由 SenseVoice 转写为目标词，Aria 的标准 `Tree` 音频被转写为 `three`；同一词的 Guy 音频和两套声音的 Whisper small 均转写为 `tree`，故存在已知正常音频的误识别。试读页始终不把文字差异判为发音错误。

为便于零基础试读，新增 `http://127.0.0.1:18768/`：常见词置前，中文意思先于英文；点英文正常播放当前词，紧邻慢速按钮以 0.72 倍速度并保持音高播放。公开词音频只从本机只读白名单返回，录音开始时停止示范播放。不会读的词可以跳过，不计入准确性判断。Chrome 假麦克风回归确认音频可播、语速切换、浏览器录音到真实服务的结果，以及 320／390／1280 像素无横向溢出；真人麦克风的新词验收仍待进行。

随后用户明确反馈：已在新版页面试读自己熟悉的词，页面识别正确。这是一次真人体验的正向自述；由于页面不保存逐次结果，尚不知道本次词目、独立录音数量和错误次数，不能换算成真人识别准确率，也不能据此验收逐音纠错。当前下一项独立工作是解决或隔离标准 `Tree` 被识别为 `three` 的反例，并找到可靠的具体错音评测能力；此前已授权的两段录音不会被自动扩大成后续保存授权。

## 交付边界

本轮只新增实验脚本、结果与文档。正式课程、学习记录、安卓和当前试读引擎未替换，提交推送仍暂停。后续验收应使用新增且独立的真人录音，不能把同一段音频的三次重复当成三个独立正确样本。

检查已完成：三个实验脚本通过 Python 编译检查；隔离环境 `pip check` 无依赖冲突；Qwen 与 SenseVoice 报告各有 48 个唯一公开用例及 3 类控制，私人用例未混入公开报告；私人结果和模型文件均被 Git 忽略。`npm run verify` 通过，3,620 个词汇、两套各 7,241 个现用音频及 592 个基础英语音频保持完整。未修改前端或安卓，本轮未重复声称浏览器、手机或正式课程发音验收通过。
