# 开源发音评测与腾讯对照（2026-09-25）

## 结论

没有一个原版方案已达到“低延迟、准确指出错音、正常读法不误判”的课程验收要求。若继续开发免费方案，优先研究 **OpenPronounce 的独立音素识别组件**：本机每条约 0.225 秒，能区分本轮全部 10 个错误样本的目标音差异；但原版反馈只对其中 1 个报错，且正常样本也存在底层识别偏差。这个结果支持继续验证，不能宣称 100% 准确或直接上线。

现成完整流程方面，腾讯响应稳定且本轮正常样本没有明确错音标记，但仍漏报易混音；pronounce-assess 会误报正常 Goodbye；GOPT 只完成官方特征数据评测，尚不能参与课程录音的质量或全链路速度排名。

## 同一组课程音频实测

采用腾讯原有 24 个公开合成样本，14 个正常读法、10 个易混词对照，Aria / Guy 各一套。逐文件核对原计划 SHA256，统一以 FFmpeg 转为 16 kHz 单声道 int16 PCM，再转 float32；输入完整保留。没有真人录音上传、没有新增云端调用或费用。

| 方案 / 原版配置 | 14 个正常样本被报错 | 10 个错误样本被报错 | 中位延迟 | P95 |
|---|---:|---:|---:|---:|
| 腾讯新版，严格度 1.5，历史实测 | 0 | 3 | 0.607 秒 | 0.706 秒 |
| pronounce-assess，整段输入 | 2 | 4 | 0.286 秒 | 0.304 秒 |
| pronounce-assess，官方示例的约 0.5 秒分块 | 4 | 4 | 0.318 秒 | 0.334 秒 |
| OpenPronounce，仅原生音素评测组件 | 0 | 1 | 0.225 秒 | 0.239 秒 |
| OpenPronounce，完整流程 + 官方支持的本地 Piper 示范音 | 0 | 1 | 0.842 秒 | 0.886 秒 |

“报错”指腾讯的明确音素错配标记、pronounce-assess 的 mispronounced/omitted、OpenPronounce 的 errors 输出。不是统一分数门槛，不等于整体识别准确率，也不意味着没报错就应该通过。分块 pronounce-assess 对 bed→bad 报的是 /b/ 错误，未指出应关注的元音，不能把该样本记为正确定位错音。

腾讯延迟是实时上传完录音后的等待，另有连接中位耗时 1.493 秒；连接、音频和结果合计中位 3.680 秒。开源延迟是模型已加载、录音已完整到达后的本机计算，包含该 API 自带的评测/韵律步骤，排除解码和录音；分块测试没有按真人说话速度等待。二者适合比较结束录音后的体验参考，但不是同一部署链路的严格性能比赛。

每种开源配置预热 1 次，再各跑 24 个样本两轮，共 **196 次本地评测**。两轮的完整结果一致；表中速度使用第二轮，P95 为 nearest rank。本次串行运行模型，Ryzen 5 7500F、32 GB 内存、Windows、CPU、PyTorch 6 个计算线程/1 个 interop 线程，未使用显卡。

腾讯严格度 4.0 的既有 12 条子集也保留：6 个正常样本均无明确错配；6 个错误样本中 3 个明确报错，对应 Guy sink→think、两套 sheep→ship。说完后中位 0.605 秒；正常 Hello 只有 51—60 分。它不是完整 24 条结果，不能直接以 3/6 与其它方案的 3/10 或 4/10 排名。本次未追加任何腾讯请求。

## 具体问题与改进价值

### OpenPronounce

- 独立音素模型在 10 个错误样本中都输出了关键差异：/s/ 对 /θ/、/i/ 对 /ɪ/、/f/ 对 /θ/、/ɛ/ 对 /æ/、/l/ 对 /ɹ/。但是原版采用“近似音降低错误权重 + 按整词比例触发”的规则，只对 Aria free→three 生成错误反馈。
- 正常样本的原始音素并非全对：两套 Hello 的元音、Aria Goodbye 的元音、Guy bad 的元音与参考不同。原规则容忍了这些差异。因此不能简单改成“音素字符串不同就判错”，也不能在这 24 条上挑阈值后声称通用准确。
- 完整流程把正常 Goodbye 转成 `GOOD BYE`，把正常 right 转成同音词 `RITE`，词错误率分别记为 2 和 1；完整总分因此降到约 54—64 和 56。这属于拼写/分词问题，不能用来判定用户没有念对。
- 原版总分由 30% 声学相似度、40% 音素、30% 单词构成；声学相似度使用合成示范音。与用户要求有冲突。后续若采用，应优先验证独立音素组件、合理发音变体与音位级证据，另行校准反馈；尚未改动原评分或接入课程。

### pronounce-assess

- 整段评测约 0.286 秒，但两套正确 Goodbye 都把 /d/ 判成 /b/、随后把 /b/ 判为遗漏。
- 整段正确抓到两套 sheep→ship、light→right；sink→think、free→three、bed→bad 均未报错。
- 按官方示例分块后，额外误报正常 Aria ship 和 bad。原版流式处理没有提高本轮质量。
- 源码将 /v/ 和 /f/、/ʒ/ 和 /ʃ/ 合并，另有 top-3 候选即可标 correct 的规则；这限制了精细纠错能力。结束时未评分的音需要外层单独处理；本轮 24 条均返回了所有目标位置，未出现此类空缺。

### GOPT

实际加载官方 Librispeech 权重，按原训练数据加载器的均值 3.203 / 标准差 4.045 归一化有效特征、保持 padding，完成官方 2,500 条测试语句、47,369 个有效音素评测：音素评分与人工标注相关系数 **0.6183**，MSE **0.08347**；句子总评分相关系数 **0.7438**。接近作者公布的结果。相关系数不是“准确率 61.8%”。

评分模型本身约 0.95 毫秒，但输入已经是作者提取好的 Kaldi 特征，**不包含音频识别、强制对齐、GOP 特征提取**，不能拿它与腾讯的 0.607 秒相比。本机 WSL 未安装、没有 Kaldi/Docker，课程录音端到端评测尚未完成；没有为了这次测试变更 Windows 虚拟化或安装系统级 Linux。官方新音频教程也标注了待处理问题。GOPT 因此不列入现阶段可接入方案的排名。

## 建议次序

1. **后续免费开发：OpenPronounce 音素组件优先。** 已有速度和关键音区分证据，下一关应是真人正常口音与真实错音的独立验证，验证集不能只用这批合成音。解决合理变体与反馈漏报后才能考虑自动判定。
2. **保留腾讯作对照。** 本次无需新增费用；严格度不能单独解决全部问题，也不能直接用总分过关。
3. **暂不投入 pronounce-assess 的课程接入。** 速度已足够，但正常 Goodbye 误报与细音合并不符合需求。
4. **GOPT 留作研究候选，完整对比未完成。** 先缺的是 Kaldi 原始音频链路，而不是评分头是否跑得动。

目前没有把任何候选模型启用为正式课程的自动纠错。真人多口音、噪声、短句、静音、连续录音与手机端完整链路仍未验收；提交推送仍暂缓。

- [OpenPronounce](https://github.com/Halleck45/OpenPronounce)：`74bc17ea406e6f057f15eea0e70951e1931af868`。

- 3 个 Wav2Vec2 权重均来自官方模型仓库，固定 revision 并核对 LFS SHA256。清单位于 `open-source-comparison-summary.json`；隔离依赖位于 `open-source-bench-requirements.txt`。
- 只对本机路径做适配：模型标识转到本地副本；eSpeak/Piper 的数据复制到本用户 LocalAppData/CodeWordsBench 的 ASCII 路径，避免中文路径导致初始化失败；OpenPronounce 选择其原生支持的 Piper 离线后端并复用现有 Lessac 模型。未改动上游评分函数和阈值，未安装全局 Python 依赖，未修改前端/安卓依赖。
- 测试时设置 HF_HUB_OFFLINE / TRANSFORMERS_OFFLINE，Piper 离线合成；初始化下载需要网络，完成后评测无需云端 API。
- 首次模型加载约：pronounce-assess 6.69 秒、OpenPronounce 音素组件 3.27 秒、完整流程 4.59 秒。首次推理分别约 3.46、0.41、1.96 秒。这些是单次冷启动观测，受系统文件缓存和 JIT 缓存影响，不应承诺固定值；正式本地服务需要预加载。
- 完整流程的示范音缓存由第一轮填充，第二轮的延迟基于缓存已就绪；第一次遇到新内容可能更慢。
- `tools/benchmark_open_pronunciation.py`：4 种配置各 2 轮。`tools/benchmark_gopt_features.py`：官方特征集评测。`tools/summarize_open_pronunciation.py`：只汇总本地产物，无云端请求。
- 原始输出：`pronounce-whole-benchmark.json`、`pronounce-stream-benchmark.json`、`open-phones-benchmark.json`、`open-full-benchmark.json`、`gopt-official-features-benchmark.json`。
- 真实评分结果、输入哈希、每条耗时与重复轮次均已保留。依赖一致性 `pip check`、脚本语法检查和 `npm run verify` 通过。没有运行或宣称本轮手机/真人回归通过。
