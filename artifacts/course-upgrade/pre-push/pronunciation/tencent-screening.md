## 方法

使用 [新版 WebSocket 接口](https://cloud.tencent.com/document/product/1774/107497)，`16k_en`、`eval_mode=4`（单词音素纠错）、`score_coeff=1.5`、PCM16 单声道 16 kHz，40 ms 实时节奏上传。

14 个正确样本 + 10 个已知错误单词对照，共 37.34 秒；均来自现有公开 Aria/Guy 课程音频。合成语音只能用于初筛，不能代表学习者口音表现。没有针对样本选定课程通过阈值。

全部请求通过 Windows 物理以太网接口 9，禁用客户端代理，保留 TLS 校验。DNS 使用当前系统解析。此证据不代表手机网络已验收。

## 精度证据

14 个正确样本都没有返回明确的音素替换/缺失标记；这不等于所有音都被独立确认正确。两种正确 Goodbye 的 `/d/` 均存在，原始音素分数约 0.972 / 0.993。

10 个错误单词样本中，只有 3 个返回了明确的识别音与标准音差异：Guy 的 sink → think，以及两种声音的 light → right。其余 7 个没有明确音素替换标记，但部分出现分数下降。因此 3/10 是“明确纠错标记数量”，不是泛化准确率。

| 实际读音 → 评测目标 | Aria 整词分数 | Guy 整词分数 | 逐音结果 |
| --- | ---: | ---: | --- |
| sink → think | 76.7 | 93.1 | Aria 保留 th 标签但降分；Guy 明确返回标准 th、实际 s、MatchTag=3 |
| sheep → ship | 90.1 | 88.9 | 都保留 ih 标签，无明确错误标记；该音分数下降 |
| free → three | 66.3 | 79.1 | 都保留 th 标签，无明确错误标记；目标音分数下降 |
| bed → bad | 95.2 | 97.3 | 都保留 ae 标签，目标音仍约 0.929 / 0.964，容易漏错 |
| light → right | 88.3 | 88.0 | 都明确返回标准 r、实际 l、MatchTag=3 |

正确 Guy Hello 的整词分数仅 72.0，其中某音原始分数约 0.409；简单提高总分或统一音素门槛会误伤正确样本。错误 Guy sink 的实际 s 反而有约 0.986 的音素分数，必须同时看实际/标准音与 MatchTag，不能只看分数高低。

本轮响应顶层与音素准确度实际为 0—1、整词准确度为 0—100，原始值完整保存，不按旧数据结构说明盲目统一量纲。

## 追加严格度对照：12 次 / 0.06 元

保持音频、模式、参考词、传输方式不变，将 `score_coeff` 从 1.5 调到 4.0。用户明确批准追加预算，脚本分别限制首轮 24 次与对照 12 次，合计最多 36 次 / 0.18 元；不能把对照预算拿来重复首轮。12 次全部返回结果，说完后响应中位数 0.605 秒。腾讯控制台已核对两轮累计调用量为 36 次。

| 样本（两种声音） | 严格度 1.5 整词分数 | 严格度 4.0 整词分数 | 对照结论 |
| --- | --- | --- | --- |
| 正确 Hello | 84.2 / 72.0 | 59.7 / 51.0 | 正常读法明显降分，不能用整词统一门槛判失败 |
| 正确 ship | 99.2 / 99.3 | 96.5 / 96.6 | 无明确错音标记 |
| 正确 bad | 98.7 / 98.9 | 93.8 / 95.0 | 无明确错音标记 |
| sink → think | 76.7 / 93.1 | 60.6 / 90.8 | 仍仅 Guy 明确返回 s 替代 th；Aria 降分但没有替换标记 |
| sheep → ship | 90.1 / 88.9 | 85.9 / 85.8 | 两种声音均新增明确 iy 替代 ih 标记，说明严格度会影响纠错输出 |
| bed → bad | 95.2 / 97.3 | 79.0 / 87.7 | 分数下降但仍标为 ae，没有明确指出 eh 替代 ae |

因此不能说调参毫无效果；也不能据此认定所有学习者都能准确通过或得到可靠的逐音指导。下一步若继续腾讯，应进行受控真人录音校准，尤其正常 Hello/Goodbye、短长元音及正常口音变体；需另获个人录音上传与计费预算授权。本轮不扩展供应商，不继续盲调或购买套餐。
