# 真人失败后的替代模型实测（2026-09-25）

当前选择 **Whisper small int8 + CROTTC-IF 的声学 CTC 分支**作为下一轮单词试验。它改善了已授权的一段真人 Goodbye 录音，但尚未达到完整课程发音评测要求。正式课程、学习记录及提交推送状态未改变。

## 固定输入与可追溯性

- 原有 24 个公开单词样本：14 个正确读法、10 个易混音对照，沿用腾讯实验计划与 SHA256，不增加云端调用。
- 新增 SpeechOcean762 官方 test 中的 24 段成人真人录音，13 位说话人，按固定 ID 顺序选择，每人最多 2 段。12 段各音均分至少 1、整句准确度至少 8；另 12 段至少一个音均分不高于 0.4。选择发生在模型推理前，见 `replacement-human-plan.json`。
- 原数据说明中，2 表示正确，**1 表示有重口音但正确**，0 表示错读或漏读。不能把 1 分一律作为错误；专家平均分中间区间也不能伪装为精确的二元音素标注。
- 用户仅授权一段录音的本机临时保存与诊断。该音频与详细结果只在 `.runtime/pronunciation/private-diagnostic/`，不进入本报告的公开 JSON，也没有上传。
- 实验进程禁止 socket 连接与 DNS 查询，模型离线加载，未发送目标文本提示给转写模型。

## 组合策略结果与失败

| 固定组 | 得到支持 | 提示练习 | 未确认 | 总数 | 中位耗时 |
|---|---:|---:|---:|---:|---:|
| 公开正确单词 | 10 | 0 | 4 | 14 | 1.608 秒 |
| 公开错误单词 | 0 | 8 | 2 | 10 | 1.606 秒 |
| 专家认可的真人句子 | 1 | **1 次误报** | 10 | 12 | 1.963 秒 |
| 含明显错音的真人句子 | 0 | 2 | 10 | 12 | 1.984 秒 |

失败证据完整保留在 `crottc-feedback-evaluation.json`，版本为 `crottc-whisper-feedback-v1`，不以之后的范围限制覆盖。误报发生在 `human-001570024` 的 found：转写得到 find，音素模型也支持 `/aʊ/`→`/aɪ/`，但所选专家分数仍属于有口音的正确读法。这再次证明两个模型相互支持仍不能替代专家校准。

正确单词中 ship 两声线、three 两声线尚未得到支持；错误单词中 bed→bad 两声线未确认。因此即使限定为单词，也不能宣称全面达标。静音、固定随机噪声和纯音均未被支持或提示具体错音。

用户原始 Goodbye 在组合策略中得到支持（1.717 秒），经过最终本机 HTTP 服务再次复现得到支持（1.652 秒）。这是**一段既有真人录音的改善**，不是新的多单词真人麦克风验收，也没有人工音素标注证明所有发音细节正确。

随后用户重新试读 Goodbye，反馈“应该没什么问题”。单独记录为该词的真人试读体验正向反馈；本次页面结果、次数与耗时尚未独立核对，不并入上述固定样本统计。Hello、Think、Ship、Three 等其他词的用户试读仍待确认。

### 后续真人失败与 v2 修复

用户继续反馈“其他的词识别很差”，因此本轮真人验收未通过，不能以 Goodbye 单词成功推广到课程。现场 Three 显示未确认、耗时 3.2 秒；在用户单独授权后，仅将当前这一段 Three 临时保存在本机已忽略的诊断目录，未上传，也未扩大为持续保存录音。

本机复现发现：Whisper 原始候选为 Three，但平均对数概率 -1.0245 未达到原有大于 -1 的门槛，文字结果被过滤；CROTTC 的音序列也与目标不一致。补 300 ms 静音和调整增益均未解决文字置信度问题。另一已下载模型 PhoneticXeus 对同一录音仅输出一个音，亦不能替代当前模型。上述模型输出不是人工发音标注，不能据此断言用户读错。

另发现独立程序缺陷：公开 Guy Three 的音序列正确，Whisper 写为数字 3，却被只提取英文字母的词典流程丢弃。`crottc-whisper-word-v2` 将孤立的 0—20 整数规范为对应英文单词，不使用目标答案提示；保留原始转写候选并明确标注低置信度，判定阈值保持不变。已识别词但音素冲突、低置信度文字、识别为其他词三类原因分开返回，未确认提示不再反复要求用户重读。

修复后重新跑原 24 个公开单词样本：正确 14 个中 11 个支持、3 个未确认；错误 10 个中 8 个提示练习、2 个未确认，无错误放行。修复了 Guy Three 的数字表示问题，Ship 两声线及 Aria Three 仍未确认；这是开发回归集，不能作为独立准确率。新结果保留在 `crottc-whisper-word-v2-evaluation.json`，旧失败证据不覆盖。静音、随机噪声、纯音均未被放行。

用户 Three 在 v2 真实 HTTP 链路复测仍未确认（3.341 秒），原始候选 Three 可见但不参与判定。4 项针对性回归、9 项真实本机 API 检查、浏览器录音链路和取消流程通过；低置信度候选展示使用明确标注的模拟响应验证，不能算真人成功。320/390/1280 页面检查、项目完整性检查及生产构建通过；构建仍有超过 500 kB 的分包提示。当前线上本机试读服务为 v2，原课程接入和提交推送继续暂停。

## 当前试读版本与验收

`crottc-whisper-word-v1` 明确仅接受单个词；整句返回 `single-word-only`、未确认、空纠错列表。只限制试验范围，未修改原来的判定阈值。试读地址为 http://127.0.0.1:18766/ ，旧模型在 18765，不能混淆测试结果。

- 8 项本机 API 检查通过，包括词例、易混元音、Host/Origin/令牌校验、异常输入及整句不判错。
- 公开 Goodbye 通过 Chrome 模拟麦克风、MediaRecorder、真实本机 API 与新模型返回支持，1.849 秒。
- 320/390/1280 像素无横向溢出；取消录音、取消后的迟到权限回调释放正常，无页面脚本错误，结果截图已检查。
- Python 编译、隔离环境 `pip check`、`npm run verify` 通过。没有修改正式 React/Android 课程；本轮不是安卓或手机真机验收。
- 新录音页仍只作内存评测，不自动留存后续录音。此前单段保存许可不扩大为持续保存。

启动：`.runtime/pronunciation/mdd-venv/Scripts/python.exe -X utf8 tools/serve_pronunciation_lab.py --engine crottc --port 18766`。模型依赖只安装在项目隔离环境，完整版本记录位于 `.runtime/pronunciation/mdd-environment.txt`。来源要求的 huggingface_hub 版本与 transformers 冲突，使用兼容的 0.36.2；HyperPyYAML 与 ruamel.yaml 0.19 不兼容，固定为 0.18.6。
